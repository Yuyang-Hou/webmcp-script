# GPT 界面优化调研与本产品设计约束

调研日期：2026-09-10。

OpenAI 的 [Frontend prompt instructions](https://developers.openai.com/api/docs/guides/frontend-prompt) 建议工具类界面围绕工作流程组织信息，控制装饰，使用熟悉的控件并检查不同视口。其 [模型指导](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.5) 也要求渲染后检查布局、裁切与一致性。

以下是针对本产品的设计判断，不是对官方 UI 的复刻。

| 方案 | 本轮选择 |
|---|---|
| 提示词约束 + 原生 HTML/CSS + 截图迭代 | 采用。当前产品足够小，可以直接统一布局、间距、颜色和交互。 |
| 引入组件库并整体迁移框架 | 暂不采用。现有原生表单、dialog、details 能完成所有真实操作。 |
| 生成图片或营销视觉 | 暂不采用。用户主要任务是安装、检查和管理脚本，不需要装饰图。 |

## 可复用设计 brief

目标用户是使用 AI 客户端的网站工具使用者。首屏先回答“有哪些脚本、现在是否启用、如何导入”，连接参数放在设置。只用中性背景和一个绿色状态强调色；不要把说明区堆成卡片。行布局呈现名称、标识、版本、范围和状态。高频操作直接可见，源码、更新、恢复、卸载放在管理菜单。操作必须保留加载、错误、确认与取消；键盘焦点明显。390px 宽度无水平溢出。

## 验收方式

真实 Chrome 扩展 E2E 检查搜索无结果及恢复、状态筛选、卸载取消与确认、安装预览及更新恢复；输出桌面、窄屏和错误状态截图。测试只证明列出的功能和视口，不代表所有用户已认可审美。后续根据真实反馈继续调整。
