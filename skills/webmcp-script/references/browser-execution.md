# 浏览器执行与取证

复用可用且已授权的浏览器工具，按其当前文档执行；不要依赖未公开的调试接口。
先选准实际页面、origin、路由、账号及环境。新标签页不等于新的账号或授权范围。
需要登录、权限或安全提示人工介入时停止该步骤，不另建通道绕过。

优先使用页面现有请求客户端；已验证无需额外签名时可用页面上下文 fetch，
配合 `credentials: 'include'`、`redirect: 'error'` 和 `AbortSignal.timeout(...)`。
这不会自动解决 CSRF 或签名；不导出浏览器凭据供独立 CLI 使用。
即使 GET 也应先核对业务语义，个人数据还需验证账号和对象所属范围。

保留有界的请求路径、参数、响应字段与部署源码片段，避免完整 HAR、凭据及个人响应。
保存代码作为文件后按原字节加载，避免手工重复粘贴或 shell 插值改变脚本。
调试器观察、网络取证与业务执行可分别使用，不要求录制或全站逆向。

离线可使用 Node 标准库 `node:test`、`node:vm` 和模拟 fetch 检查已审阅代码。
VM 不是不可信代码安全沙箱；mock 成功不能替代真实页面调用。
写请求返回成功后仍需回读业务状态，异步受理不等于发布完成，更不等于终端验收。
